# ContextLoom v2.4.0

**A context-aware coding agent harness — TUI + GUI, prebuilt for every platform.**

## Highlights

- **Linux builds actually work now.** The `internal/sandbox` Linux resource-limit path
  referenced a non-existent `syscall.SysProcAttr.Rlimit` field, so **every `GOOS=linux`
  target failed to compile** and no Linux binary had ever shipped. Fixed by injecting the
  POSIX-portable `ulimit` preamble (`-v`/`-n`/`-t`) into the shell command, which applies
  limits to the whole forked process tree without the race of parent-side `Prlimit`.
  → This release ships **14 Linux TUI binaries** for the first time.
- **Full 24-target TUI matrix** built and verified (darwin, linux, windows, freebsd,
  netbsd, openbsd, dragonfly, solaris, aix).
- **GUI binaries** for macOS (arm64 + amd64) and Windows (amd64 + arm64, GUI subsystem —
  no console window on double-click).
- **Unified version reporting.** `pkg/version` is now the single source of truth; the MCP
  client no longer hardcodes a stale version string, and the macOS `.app` plist is aligned.

`contextloom-<os>-<arch>[.exe]` = **TUI** · `contextloom-gui-<os>-<arch>[.exe]` = **GUI**

> **Linux GUI** is intentionally not prebuilt: Wails binds the system WebView (GTK3 /
> WebKitGTK), so a portable binary cannot cover distro version differences. Build it from
> source with `-tags production`; on a headless host it falls back to browser mode.

## Install

```bash
# macOS / Linux TUI — no Go toolchain needed
chmod +x contextloom-linux-amd64 && ./contextloom-linux-amd64 --version
```

```powershell
# Windows GUI — keep the backend beside the launcher
# contextloom-gui-windows-amd64.exe + contextloom-windows-amd64.exe in the same folder
.\contextloom-gui-windows-amd64.exe
```

The GUI locates its `contextloom` backend next to its own executable first; override with
`CONTEXTLOOM_BIN=/path/to/contextloom` if they live apart.

## Verify

```bash
./contextloom-darwin-arm64 --version    # contextloom v2.4.0
sha256sum -c SHA256SUMS                 # integrity of all attached binaries
```

## Known limitations

- **Plan 9** is not shipped: the upstream `charmbracelet/x/term` dependency has no plan9
  implementation (`undefined: state/isTerminal/makeRaw`), so the TUI cannot link there.
- **Linux GUI** must be built on target (WebView/CGO), see above.

# ContextLoom v2.4.0（中文）

**上下文感知的编码 Agent 框架 —— TUI + GUI，全平台预编译。**

## 重点更新

- **Linux 构建终于可用。** `internal/sandbox` 的 Linux 资源限制路径引用了并不存在的
  `syscall.SysProcAttr.Rlimit` 字段，导致**所有 `GOOS=linux` 目标编译失败**，此前从未
  产出过任何 Linux 二进制。现改为向 shell 命令注入 POSIX 便携的 `ulimit` 前缀
  （`-v`/`-n`/`-t`），由 shell 对整棵进程树施加限制，避免父进程侧 `Prlimit` 的竞态。
  → 本次**首次发布 14 个 Linux TUI 产物**。
- **24 目标 TUI 矩阵**全部构建并验证（darwin / linux / windows / freebsd / netbsd /
  openbsd / dragonfly / solaris / aix）。
- **GUI 产物**：macOS（arm64 + amd64）、Windows（amd64 + arm64，GUI 子系统——双击无黑窗）。
- **版本号统一**：`pkg/version` 成为唯一来源，MCP 客户端不再硬编码旧版本号，
  macOS `.app` 的 plist 也已对齐。

## 下载

`contextloom-<os>-<arch>[.exe]` = **TUI** · `contextloom-gui-<os>-<arch>[.exe]` = **GUI**
（平台对照表见上方英文部分，命名一一对应。）

## 安装

```bash
# macOS / Linux TUI —— 无需 Go 工具链
chmod +x contextloom-linux-amd64 && ./contextloom-linux-amd64 --version
```

> **GUI 必须与后端同目录**：`contextloom-gui` 与 `contextloom` 放在一起，
> 或用 `CONTEXTLOOM_BIN=/path/to/contextloom` 指定。Windows GUI 双击启动不会弹出黑窗。

## 已知限制

- **不提供 Plan 9 产物**：上游 `charmbracelet/x/term` 无 plan9 实现（`undefined: state` 等），
  TUI 在该平台无法链接。
- **Linux GUI** 需在目标平台自行构建（WebView/CGO 依赖），见上。
